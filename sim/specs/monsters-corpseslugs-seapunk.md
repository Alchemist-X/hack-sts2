### 2.2 Move graph (`GenerateMoveStateMachine`, `:420-438`)

| State | Kind | Intents | Effect (sim call) | Follow-up | Citation |
| --- | --- | --- | --- | --- | --- |
| `WHIP_SLAP_MOVE` | Move | `MultiAttackIntent(3, 2)` | `DamageCmd.Attack(cs, 3).WithHitCount(2).FromMonster(self).Execute()` | `GLOMP_MOVE` | `:423`, `:426`; body `:303-309` |
| `GLOMP_MOVE` | Move | `SingleAttackIntent(GlompDamage)` | `DamageCmd.Attack(cs, GlompDamage).FromMonster(self).Execute()` | `GOOP_MOVE` | `:424`, `:427`; body `:145-149` |
| `GOOP_MOVE` | Move | `DebuffIntent()` (not strong → `IntentType.Debuff`, `MonsterMoves.Intents/DebuffIntent.cs:11-15,23-26`) | `PowerCmd.Apply<FrailPower>(cs, targets, 2, self, null)` | `WHIP_SLAP_MOVE` | `:425`, `:428`; body `:230` (anim, dropped), `:246` |

- Registration order `WHIP_SLAP, GLOMP, GOOP` (`:429-431`). No branch state, so the AI never draws from
  `MonsterAi`; the sequence is a fixed 3-cycle from the initial move.
- Initial state: `(StarterMoveIdx % 3) switch { 0 => WHIP_SLAP, 1 => GLOMP, _ => GOOP }` (`:432-437`). C#
  `%` keeps the sign, so a negative index other than a multiple of 3 lands on `GOOP` (ported as written;
  only 0..2 occur). The initial state is a move state, so it is logged when the runtime is built and the
  first `RollMove` keeps it (`monsters.md` §3).
- `targets` of `GOOP` is the move's target list = `CombatState.PlayerCreatures` (`Models/MonsterModel.cs:269`,
  `Combat/CombatState.cs:560`); the sim passes `MonsterLifecycle.PlayerCreatures(cs)` = `[cs.Player]`. The
  multi-target `PowerCmd.Apply<T>` is a plain loop (`Commands/PowerCmd.cs:1185-1212`), same in the sim.
- `FromMonster` targets all opponents; `WithHitCount` before or after `FromMonster` is order-free.

### 2.3 `AfterAddedToRoom` (`:407-418`, body in the state machine `:41-108`)

`await base.AfterAddedToRoom()` (`:72`; the base returns `Task.CompletedTask`, `Models/MonsterModel.cs:604-607`),
then `PowerCmd.Apply<RavenousPower>(Creature, RavenousStr, Creature, null)` (`:88`). Sim:
`CorpseSlug.AfterAddedToRoom(cs, self)` = `PowerCmd.Apply<RavenousPower>(cs, self, RavenousStrength(cs), self, null)`.
It runs from `MonsterLifecycle.AfterCreatureAdded` during `StartCombat` (setup window: `PowerCmd.Apply` is not
gated there, `monsters.md` §5), once per slug in creation order, each followed by that slug's first
`RollMove`.

### 2.4 `EnsureCorpseSlugsStartWithDifferentMoves(monsters, rng)` (`:480-498`)

`OfType<CorpseSlug>` (`:482`); `num = rng.NextInt(3)` **before** the enumeration (`:483`, one draw even with
no slug); for each slug in list order `StarterMoveIdx = num % 3; num++` (`:487-492`). Sim:
`CorpseSlug.EnsureCorpseSlugsStartWithDifferentMoves(IReadOnlyList<MonsterSpawn>, Rng)` returns a new spawn
array; each `CorpseSlug` spawn gets a `Configure` that runs the spawn's previous `Configure` and then sets
`StarterMoveIdx` (the game sets the field on the mutable model before `CreateCreature`); other spawns pass
through unchanged. `NextInt(3)` = `NextInt(0, 3)` (same kernel call, `Random/MegaRandom.cs` `Next(max)`).

## 4. `RavenousPower` (`Models.Powers/RavenousPower.cs`)

| Member | Value | Citation |
| --- | --- | --- |
| `Type` | `Buff` | `:211` |
| `StackType` | `Counter` | `:213` |

`AfterDeath(target, wasRemovalPrevented)` (`:221-235`, state-machine body `:38-138`):

1. Guard (`:71`): act only if `!wasRemovalPrevented && target != Owner && target.Side == Owner.Side && !Owner.IsDead`.
2. `Flash()` (`:73`), sfx (`:74`), `await TriggerAnim(Owner, "DevourStartTrigger", 0.5f)` (`:75`): dropped.
3. `((CorpseSlug)Owner.Monster).IsRavenous = true` (`:116`).
4. `await CreatureCmd.Stun(Owner, StunnedMove)` (`:117`).
5. `PowerCmd.Apply<StrengthPower>(choiceContext, Owner, Amount, Owner, null)` (`:105`).

`StunnedMove` (`:237-248`, body `:159-202`): sfx (`:175`), anim (`:176`), then
`((CorpseSlug)Owner.Monster).IsRavenous = false` (`:192`).

Sim: `RavenousPower.AfterDeath(cs, creature, wasRemovalPrevented)` with the same guard, then
`CorpseSlug.GetExtra(owner).IsRavenous = true`, `CreatureCmd.StunWithMove(cs, owner, StunnedMove)` (no explicit
next move id), `PowerCmd.Apply<StrengthPower>(cs, owner, Amount, owner, null)`; the static `StunnedMove(cs, self, _)`
clears `IsRavenous` on the performing monster (= the power's owner). The game's hard casts throw for a
non-CorpseSlug owner; the sim throws `InvalidOperationException` there (unreachable in these encounters).

`CreatureCmd.Stun(creature, stunMove, nextMoveId)` (`Commands/CreatureCmd.cs:4105-4111`) calls
`Creature.StunInternal(Wrapper, nextMoveId)` (`Entities.Creatures/Creature.cs:1105-1126`): default next move =
last `StateLog` entry; a transient `STUNNED` `MoveState` (`StunIntent`, `FollowUpStateId`,
`MustPerformOnceBeforeTransitioning = true`) set through `SetMoveImmediate` (`Models/MonsterModel.cs:724-736`).
The decompile drops the body of the local `Wrapper`; the IL of
`CreatureCmd/<>c__DisplayClass27_0/<<Stun>g__Wrapper|0>d::MoveNext` shows it only creates an `NStunnedVfx`
(`IL_0014`-`IL_0065`, Godot, skipped when no node exists) and then awaits `stunMove(c)` (`IL_006a`-`IL_0076`).
So the sim's `CreatureCmd.StunWithMove` → `MonsterLifecycle.StunInternal` running `stunMove` directly is exact.
This closes the open question in `pipeline.md` §9 about the wrapper body.

Hook dispatch and ordering come from the pipeline port: `CreatureCmd.Kill` calls `Hook.AfterDeath(…, false)`
before the dead creature leaves the combat and before its powers are removed
(`Commands/CreatureCmd.cs:2782` vs `:2817`/`:2821` and `:2826`). Consequences, all tested:

- Killing one slug on the player's turn stuns the other: its pending move `X` is replaced by `STUNNED`
  (follow-up `X`), it gains `RavenousStrength` Strength, the stun survives the next player-turn re-roll,
  the enemy turn performs `STUNNED` (no effect but `IsRavenous = false`), and the next roll returns to `X`
  (`StateLog` `[X, X]`).
- A teammate dying after the survivor already acted this enemy turn (Doom at the end of the enemy turn)
  stuns it with follow-up = the move it just performed, so after the stun it repeats that move
  (default next move = last `StateLog` entry, `Entities.Creatures/Creature.cs:1114-1118`). Recorded: session `1785575328-8UA4FD2WAT` (v0.107.1, A7, floor 4): slug 2 died
  of Doom after both slugs acted in round 3; slug 1 gained Strength 4 on the enemy side and was `STUNNED` in
  round 4.
- Both slugs dying in one damage call: the first death's dispatch sees the second slug already at 0 HP
  (`Owner.IsDead`), and the second death finds the first slug's power already removed: no stun, no Strength.
- The dying slug's own Ravenous is still a listener during its death and is skipped by `target != Owner`.

## 5. Encounters

### 5.1 `CorpseSlugsWeak` (`Models.Encounters/CorpseSlugsWeak.cs`)

`IsWeak => true` (`:17`), `RoomType => Monster` (`:15`); `Tags` (`:13`, `EncounterTag.Slugs`) and
`AllPossibleMonsters` (`:19`) are run-level data, not ported. `GenerateMonsters` (`:21-38`): two mutable
`CorpseSlug`s with `null` slot (`:32`, `:34`), then `EnsureCorpseSlugsStartWithDifferentMoves(…, base.Rng)` (`:36`).

`base.Rng` is the encounter-private `Rng`, created in `GenerateMonstersWithSlots` as
`new Rng((ulong)((long)runState.Rng.Seed + (long)runState.TotalFloor) + GetDeterministicHashCode("CORPSE_SLUGS_WEAK"))`
(`Models/EncounterModel.cs:211-215`; legacy formula `rng-encounter-private.md` §3.3). The infra seam exists
at build time: `CorpseSlugsWeak` overrides `EncounterDef.GenerateMonsters(CombatState, Rng)` and its
one-argument overload throws `EncounterRngRequired()`; `MonsterSpawner.SpawnEncounter` hands it
`context.CreateEncounterRng(cs.Rng.Seed, Id)`. Exactly one draw (`NextInt(3)`), so slug 1 starts at
`k = NextInt(3)` and slug 2 at `(k + 1) % 3`: the two slugs always open with different moves and walk the
cycle one step apart.

Spawn (`monsters.md` §4): slug 1 then slug 2, each `CreateCreature` + add before the next
(`Rooms/CombatRoom.cs:381-394`): **one `Niche` draw per slug in creation order**, the second excluding the first
slug's HP (`Combat/CombatState.cs:717`, `Entities.Creatures/Creature.cs:972-984`). Combat ids 1, 2. No slots, so
no slot sort. The first `RollMove`s draw nothing.

## 7. Oracle checks against the recorder corpus (read-only, nothing from the corpus is committed)

1. **Starter moves vs the encounter `Rng`.** For every recorded `CORPSE_SLUGS_WEAK` fight with a derivable seed
   (40 fights: 33 v0.107.1 legacy, 7 v0.110.1/v0.111.0 XXH64; floors 2-12; one `old`-prefixed continuation
   skipped), the first battle snapshot's intents (`3×2` = WHIP, single attack = GLOMP, Debuff = GOOP) equal
   `[k, k+1]` with `k = NextInt(3)` on the encounter `Rng` seeded from `room_entered.data.floor`: 48/48
   snapshot windows (session parts included). Pinned: `Test_CorpseSlugsSeapunk_RecordedSlugStartersMatchEncounterRng`.
2. **Move sequences.** Replaying `monster_performed_move` events against the cycle + Ravenous-stun model:
   47/48 `CORPSE_SLUGS_WEAK` windows and 32/32 `SEAPUNK_WEAK` windows match directly; the remaining window is the
   Doom case of §4, consistent with the follow-up rule.
3. **Values.** Snapshot/event values agree with §2-§3 at every ascension seen (A1-A10): slug HP 25-27 / 27-29
   (always distinct), Ravenous 4 / 5, GLOMP 8 / 9, WHIP `3×2`, Frail 2 to the player; Seapunk HP 44-46 / 47-49,
   SEA_KICK 11 / 13, BUBBLE_BURP block 7 / 8 (13× A8+ = 8, 8× below = 7) and Strength 1 / 2 on itself.
4. **Diff bundles.** The 32 exporter bundles of these encounters (all floor 2; marked ineligible for the Ironclad
   harness because of character or relics, which do not touch the monster side) were replayed through
   `RngSetup.Create` + `rng_offsets` + `CombatSim.Create(rng, …, CombatRunContext.ForAct(1, 2, …))` with the
   recorded deaths injected (`CreatureCmd.Kill`) and enemy turns performed: opening HP/max HP exact in every
   bundle with an opening pre-state (including `Niche` offsets 6 and 7, both seeding schemes), Ravenous amounts
   exact, 252/252 attack-intent values exact, intent types on 333/346 decisions; the 13 others are all in one
   fight (`1786177674-8NQJD8BQKU`) where the player applied −2 Strength to the slug, which the oracle does not
   replay. Eleven player-turn kills reproduced the `STUNNED` intent and the Strength gain. Ten openings are
   pinned in `Test_CorpseSlugsSeapunk_RecordedFirstStatesMatch`.
5. **Random playouts** (not a corpus check): 4000 `CombatSim` games (both encounters, A0/5/8/9/10, 400 seeds,
   uniform random legal actions, 83k steps) ran without exceptions; replays from the same seed and actions gave
   the same final hash; 11,830 clone checks kept equal hashes and source independence; at every decision point
   a slug's `IsRavenous` equalled `IsStunned` (1998 of the 2000 slug games saw a Ravenous stun).

  `IntendsToAttack`; initial state for starter indices including `% 3` wrap and negative values.

  one-argument overload throws; `SEAPUNK_WEAK` draws nothing; the helper skips non-slugs, chains `Configure`,

- `CombatSim` setup: creation order, `Niche` = 2, `MonsterAi` = `CombatTargets` = 0, Ravenous on both slugs
