### 3.4 Move sequence and RNG draws

- The machine constructor logs the initial state when it is a move (`MonsterMoveStateMachine.cs:47-52`), so
  `StateLog = [OIL_SPRAY_MOVE]` before any roll; `RAND` never appears in the log (`RandomBranchState.cs:51`).
- `RollMove` returns immediately while `!_performedFirstMove && current.IsMove` (`MonsterMoveStateMachine.cs:84-87`):
  the first roll (`AfterCreatureAdded`) and the round-1 re-roll (`PrepareForNextTurn`) both yield
  `OIL_SPRAY_MOVE`, log nothing and **draw nothing**.
- From the start of player turn 2 on, every roll goes `current → RAND` (`GetNextState` = follow-up), which draws
  exactly one `rng.NextFloat(max)` on `RunRng.MonsterAi` (`RandomBranchState.cs:130-155`, `Models/MonsterModel.cs:721`).
- `CannotRepeat` weight (`RandomBranchState.cs:157-194`, `:171-186`): 0 for the move equal to the last `StateLog`
  entry, else 1. So `max = 2`, the two allowed moves are taken in branch order `OIL, SLAM, RAGE` with the
  disallowed one removed: `NextFloat(2) <= 1` → the first allowed move, else the second. (A draw of exactly
  `0` would return the first branch even if its weight is 0, `monsters.md` §3; probability 2^-53.)
- Hence: turn 1 `OIL_SPRAY`, then each turn a uniform pick between the two moves that differ from the
  previous one; one `MonsterAi` draw per player turn from turn 2; never the same move twice in a row.

### 4.4 Thorns bookkeeping of the Toadpole

- `SPIKEN_MOVE` stacks +2 on the existing instance or attaches a new one (Counter, non-instanced).
- `SPIKE_SPIT_MOVE` first applies `-2`: on an existing instance `ModifyAmount` → `2 - 2 = 0` →
  `ShouldRemoveDueToAmount` (`AllowNegative` false, amount ≤ 0) → removed (`Commands/PowerCmd.cs:1299-1357`,
  `:1322`, `:1333`; `Models/PowerModel.cs:606-617`). Only then the three hits land, so a toadpole never has Thorns while
  it spits. Recorder event order confirms: `power_received THORNS -2`, then three `damage_received`.
- Edge kept as in the game: if the toadpole has no Thorns when it spits (only possible if something removed
  them), `Apply` attaches a fresh `ThornsPower` with amount `-2` (`Commands/PowerCmd.cs` `Apply` → `ApplyInternal`
  `:455`, `Models/PowerModel.cs:674-683`; no removal check on first application). Its retaliation then deals
  `max(0, -2) = 0`.
- Thorns is a monster-owned Buff, so `SkipNextDurationTick` is never set (`Commands/PowerCmd.cs:478` only for
  player-side debuffs) and nothing ticks it down.

## 6. Shared pieces relied on (not changed)

- `WeakPower` (player): applied with `SkipNextDurationTick = true` because the target is player-side and the
  power a Debuff (`Commands/PowerCmd.cs:478`); ticks in `AfterSideTurnEnd` when `side == Enemy`
  (`Models.Powers/WeakPower.cs:56-58`, `:123`).
  So OIL_SPRAY's Weak 1 survives the enemy turn it was applied in and expires at the end of the next enemy
  turn: the player is Weak for exactly one player turn (recorder: `WEAK_POWER -1` on the next enemy side).
  A second OIL_SPRAY (never consecutive) on a still-Weak player would stack via `ModifyAmount` without the skip.
- `StrengthPower` (monster, `AllowNegative`): RAGE's +3 stacks; it raises later attack intents and damage,
  not the RAGE hit that grants it.
- `MultiAttackIntent` display: `attack_value` = single-hit damage after `Hook.ModifyDamage`, `attack_times` =
  repeats (label `3×3` / `4×3`), unchanged projector rules (`diff-harness.md` §3).
