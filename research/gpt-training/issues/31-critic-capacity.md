# [GPT research] 对照评估 Value 容量、拟合不足与完整回报校准

GitHub: https://github.com/Alchemist-X/hack-sts2/issues/31

## 假设与优先级

Value 末端 384→192→1 可能不足以表达牌组、遗物、药水与敌人的组合价值；但其前面已经有共享 Transformer。更大输出头不会自动增加记忆或信用分配距离，也不能弥补稀少后幕样本。当前证据没有证明容量是瓶颈。

## 候选方案

- 对照为现有 Value；实验候选 384→512→512→1，保留合法候选平均表示及 detach 语义。
- 用初始输出为零的残差扩容等方式保持起始预测一致；禁止成熟对照与随机重置 critic 直接比较。
- Actor、共享主干、奖励、rollout、batch、优化设置保持相同。若要测试额外 critic 更新次数，单列实验，不与扩容捆绑。

## 验收

- [ ] 用冻结策略完整自主对局形成真实剩余回报标签；按整局分割训练/验证，不能随机拆同局步而泄漏。
- [ ] 区分真实 terminal 与外部截断；标签包含实际 cycle 扣分。报告按幕/阶段分层的误差、偏差、样本数，GAE 自举误差单列。
- [ ] 核对候选 padding/空集合、梯度流向、初始函数等价与恢复兼容。
- [ ] 比较固定标签下的容量收益和在线策略收益；value loss 降低不能替代通关表现。
- [ ] 报告参数量、推理/学习耗时和显存；不以参数增幅冒充实际开销增幅。

## 共同实验约定

这是研究提案，不代表已经实现、部署或证明有效。保持 Silent A10、自主 fresh 开局、公开观测、greedy 无 search/breaker 评测；不引入人类轨迹、存档/harvest、外部模型权重或 blind 选型。使用同一父 checkpoint 的匹配对照（改变结构时控制初始化），同等新增有效环境步数，并同时报告实际计算时间和费用；有希望的结果用多个训练随机种子复验。预先固定评测节点，25M 是观察点，不设置“25M 必须达到某进度”的事后淘汰线。评价仍用原协议平均进度、各幕到达率和完整通关率。
