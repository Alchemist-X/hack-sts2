## 1. Starting point and the fork

Both lines start from the same full training state: the chosen arm's `pinned-0000764.pt` (weights, Adam state,
counters, RNG states, stream counter). Copy it into each line's `checkpoints/` as `ckpt-0000764.pt`; `--resume auto`
continues from it, and every re-run continues the line, never the source.

- Both lines continue the source's seed stream (`SP1-SILENT-<n>` from the u764 `seed_stream_next`): the k-th stream
  episode after the fork gets the same seed in both lines (common random numbers). Line B consumes the stream more
  slowly (≈1/3 of its starts are anchors, which take no stream index), so the two lines play the same seeds at
  different times; the sequence is shared.
- Each line logs the source's 2,048 in-flight episodes as `dropped` rows in its first session.
- First-session checks (`config.json` `sessions[-1]`): `rng_restored` ok for numpy / torch / cuda;
  `seed_stream_next` = the source's final counter; `dropped_at_start` 2048; `config_diff` lists exactly the intended
  flag changes (both: `out`, `max_updates`, `eval_at`, `eval_every`, `max_hours`, `ent_coef_final`,
  `ent_anneal_updates`, `ent_anneal_start`, `eval_at_every`, `pin_every`; A: `overlap` if double; B: `harvest`,
  `harvest_prob`, `harvest_start_share`). Later segments differ only in `max_updates`.
  Because the u764 checkpoint predates the W3 keys, the first session's `config_diff` also lists every new key at its
  default (e.g. `harvest: [null, ""]`, `harvest_prob: [null, 0.25]`, `harvest_max_per_step: [null, 64]` in line A);
  this is expected (seen in the remote fork gate of a 073a32b checkpoint).

### 3.1 Shared flags (the v2 recipe; changes marked)

```bash
FLAGS=(--start-mode stream --seed-stream-prefix SP1 --env-seed 1 --init-seed 1 --sample-seed 1
       --characters SILENT --ascension 10 --start-saves none
       --objective protocol --win-bonus 1.0 --acq-shaping --acq-deck-coef 0.003 --acq-relic-coef 0.01
       --acq-upgrade-coef 0.012
       --d-model 192 --state-dim 384 --depth 3 --heads 6 --ff-mult 4 --deck-counts --aux-heads --aux-coef 0.1
       --rollout 64 --epochs 1 --minibatch 4096 --lr 3e-4 --gamma 1.0 --lam 0.99 --clip 0.2 --vf-coef 0.5
       --ent-coef 0.02 --max-grad-norm 0.5 --max-rows 64 --step-cap 3000 --floor-step-cap 80
       --device cuda --amp --compile default
       --no-best --eval-at-seedset silent-a10-dev-v1 --eval-at-modes greedy-on,greedy-off
       --eval-every 100 --eval-seedset silent-a10-v1 --loop-breaker on          # changed: monitor every 100 (was 25)
       --ckpt-every 25 --ckpt-every-min 15 --keep-ckpts 40 --max-hours 3 --log-every 1   # changed: max-hours 3
       --cycle-cost "$CYC"                                                     # 0 (C0) or 0.01 (C1), §2
       # new in W3, both lines
       --ent-coef-final 0.005 --ent-anneal-updates 2300 --ent-anneal-start 764
       --eval-at-every 100 --pin-every 100 --eval-at 1264,1764,2264,2764,3064)
```

- Entropy: update u uses 0.02 + (0.005 − 0.02) · clamp((u − 1 − 764) / 2300, 0, 1), i.e. 0.02 at u765 and 0.005 at
  u3064. `--ent-anneal-start 764` is explicit, so every segment and every reconnect computes the same schedule (it is
  also stored in `config.json`; a resume continues it).
- `--eval-at-every 100` gives dev-128 greedy-on / greedy-off rows at u800, u900, …, u3000 (absolute update numbers);
  `--eval-at` adds the five comparison points. Every such row's weights are pinned (`pinned-<N>.pt`, never pruned).
  No `best.pt`; each line's deliverable is its u3064 pinned checkpoint, fixed now.

### 3.2 Line A (main) and line B (experiment)

```bash
A_FLAGS=("${FLAGS[@]}" --overlap "$OVERLAP")          # OVERLAP = double or off, fixed by the preflight (§3.3)
B_FLAGS=("${FLAGS[@]}" --overlap off
         --harvest boss:1536,elite:512,act2:1024 --harvest-prob 0.25 --harvest-start-share 0.33)
```

The only intended learning difference between A and B is harvest (`sts2train/harvest.py`): determinized clones of
this line's own boss / elite / act-2 combat entries in stream episodes, kept in FIFO rings; a finished slot restarts
from a uniformly drawn live anchor with probability 0.33, otherwise from the next stream seed. No human data, no old
model, no eval seed: anchors come only from the line's own stream episodes.

### 3.3 The overlap preflight (GPU A, before u765), and why A double / B off is a fair pair

Owner C measured the mechanism on CPU only (`t_overlap_wait_s` ≈ 0: the env step is fully hidden) and found no gain
there. The A100 gain is a projection that depends on r_inf = (lane A + lane B forward time) / one full-batch forward on
the GPU. Before line A starts, on GPU A:

```bash
python $SRC/sim/tools/train/bench/overlap_bench.py --device cuda --envs 2048 --rollout 64 --updates 6 \
    --preset small --threads 10 --torch-threads 2 --minibatch 4096 --epochs 1 --repeats 2 --out /content/bench-ov
```

Then the real recipe for 3 updates into a scratch directory, from a copy of the fork checkpoint, with `--overlap
double --compile default --max-updates 767`; check `train.log` for `compiled rollout forward vs eager: … OK` and
`t_overlap_wait_s` in `metrics.jsonl`.

- **OVERLAP=double** iff r_inf ≤ 1.4, the bench's double `t_total` is below off's, and the compile check is OK.
- Otherwise **OVERLAP=off**. Decided once, logged, never changed within the line.
- Fairness: in stream mode, double and off sample from the same policy distribution; they differ only in RNG
  consumption (two sampler calls per step instead of one) and wall time. GPU training with bf16 and `torch.compile` is
  not bitwise reproducible anyway (v2 rule 9). Comparisons are at matched update numbers = matched env steps (both
  2048 × 64 per update), so a faster line A does not get more data at a comparison point.

### 3.4 Driver per GPU (one session per 500-update segment)

```bash
#!/bin/bash
# w3_line.sh BUNDLE RUNS LINE(a|b) ARM(c0|c1) [OVERLAP]   (FLAGS / A_FLAGS / B_FLAGS as in §3.1-3.2)
set -u; B=$1; R=$2; L=$3; ARM=$4; OVERLAP=${5:-off}
CYC=0; [ "$ARM" = c1 ] && CYC=0.01
RUN=$R/w3-$L; EV="python3 -m sts2train.cli"
export STS2VEC_AOT_LIB="$B/lib/Sts2Sim.Vec.so" STS2VEC_SEEDSETS="$B/seedsets"
mkdir -p $RUN/checkpoints
[ -f $RUN/checkpoints/ckpt-0000764.pt ] || cp $R/sp2-$ARM/checkpoints/pinned-0000764.pt $RUN/checkpoints/ckpt-0000764.pt
reached() { python3 -c "import json,sys; sys.exit(0 if int(json.load(open('$RUN/status.json')).get('update') or 0) >= $1 else 1)" 2>/dev/null; }
for END in 1264 1764 2264 2764 3064; do
  tries=0
  until reached $END; do
    tries=$((tries + 1)); [ $tries -gt 4 ] && { echo "$RUN not at u$END after 4 sessions"; exit 1; }
    if [ $L = a ]; then bash $B/run_train.sh $RUN 12 2048 "${A_FLAGS[@]}" --max-updates $END || exit 1
    else                bash $B/run_train.sh $RUN 12 2048 "${B_FLAGS[@]}" --max-updates $END || exit 1; fi
  done
  CK=$(printf '%s/checkpoints/pinned-%07d.pt' $RUN $END); E=$RUN/endpoint/u$END-ab512-greedy-off
  [ -f $E/report.json ] || { rm -rf $E; $EV eval --out $E --threads 12 --device cuda --seedset silent-a10-ab-v1 \
                               --checkpoint $CK --policy greedy --breaker off; }
done
CK=$(printf '%s/checkpoints/pinned-%07d.pt' $RUN 3064)
[ -f $RUN/endpoint/u3064-ab512-greedy-on/report.json ] || $EV eval --out $RUN/endpoint/u3064-ab512-greedy-on \
    --threads 12 --device cuda --seedset silent-a10-ab-v1 --checkpoint $CK --policy greedy --breaker on
[ -f $RUN/endpoint/u3064-dev128-sample-off/repeats.json ] || $EV eval --out $RUN/endpoint/u3064-dev128-sample-off \
    --threads 12 --device cuda --seedset silent-a10-dev-v1 --checkpoint $CK --policy sample --breaker off \
    --sample-seed 1 --repeats 3
```

Each segment's session ends at a pinned comparison point (`--max-updates $END`; the entropy schedule and `--eval-at`
are absolute, so a segment boundary changes nothing but `max_updates`). The ab-512 greedy-off eval of that checkpoint
then runs on the same GPU before the next segment.

Ops, unchanged from v2 (`scratchpad/colab/`): one `gcs_sync.py --bucket gomoku-zero-20260816-ai-sts2train --prefix
runs --run $RUN --interval 60 --min-age 60` per line (setsid nohup); on the Mac one `ping_loop.sh SESSION 300` per
runtime and `mirror_loop.sh` (no checkpoints); `gcs_pull.py` restores a line onto a new VM (newest checkpoint; `--resume
auto` continues). The bucket keeps every pinned checkpoint even when `--keep-ckpts` prunes locally.

## 4. Matched-endpoint comparisons (every 500 updates)

At each of u1264, u1764, u2264, u2764, u3064, once both lines have reached it. The comparison runs where both lines'
eval directories are: VM B after a `gcs_pull` of A's `evals/` and `endpoint/`, or the raven testbox; not on the Mac.

```bash
u=$(printf 'u%07d' $N)
for m in greedy-off greedy-on; do
  python3 -m sts2train.cli compare $R/w3-a/evals/$u/$m $R/w3-b/evals/$u/$m --labels A,B \
      --json $R/cmp/dev128-$m-$u.json > $R/cmp/dev128-$m-$u.txt          # greedy-off = PRIMARY
done
python3 -m sts2train.cli compare $R/w3-a/endpoint/u$N-ab512-greedy-off $R/w3-b/endpoint/u$N-ab512-greedy-off \
    --labels A,B --json $R/cmp/ab512-greedy-off-$u.json > $R/cmp/ab512-greedy-off-$u.txt   # CONFIRMATORY
```

Pre-registered reading:

1. **Official comparison**: B − A at the fixed endpoint u3064 (`pinned-0003064.pt` of each line). u1264 … u2764 are
   trajectory points; they can trigger only the harm stop of §5.3, never a "harvest helps" claim.
2. **Primary metric**: dev-128 greedy-off fresh-start progress, the per-seed paired difference B − A with 95 % t and
   bootstrap CIs (`compare`). Also reported: clear rate (wins / 128), stage funnel, death rate per fight at the Act-1
   boss / Act-2 elites / Act-2 boss, rest-site upgrade share, UI-cycle share, greedy-on scores and the breaker's
   on / off gap per line.
3. **"Harvest helps"** at u3064 iff the dev-128 greedy-off paired 95 % t CI of B − A is entirely above 0 **and** the
   ab-512 greedy-off paired difference has the same sign with its 95 % CI not entirely below 0.
4. **"Harvest hurts"** iff the dev-128 greedy-off CI is entirely below 0 and ab-512 greedy-off points the same way.
5. Otherwise: "no detectable difference at 300 M steps".
6. **Owner goal check** (per line, u3064, dev-128 greedy-off): progress ≥ 0.60 and clear rate ≥ 0.10. If a line meets
   it on dev-128, confirm on ab-512 greedy-off. **blind-256 (`silent-a10-blind-v1`) is not evaluated in this round**;
   a goal claim on it needs a separate, user-approved `--allow-blind --purpose` run of the one delivered checkpoint.
7. Training-side numbers (`fresh_*`, `harvest_*`, training progress) are diagnostics only: line B's training episodes
   include anchor starts, so its training progress is not comparable to A's. Only the eval rows are.

**Information parity.** Both lines see the same observation encoding, the same rules, the same seed stream, the same
eval sets and protocol limits (eval step cap 1200, floor step cap 80), and the same env-step budget at every comparison
point. Harvest adds no outside information: anchors are the line's own states, determinized at capture (the hidden
state is resampled once per anchor; every start from one anchor replays that sampled state, as in pool mode). The
isolation guard keeps every holdout set (dev-128, ab-512, blind-256, test-100, …) out of the stream, and anchors are
captured only from stream episodes, so no eval seed reaches either line's training.

## 5. Stop rules

1. **Engineering stop (either line, immediate)**: NaN / inf in a loss; `sim_error` or `content_gap` > 0 on 3
   consecutive updates; `stream_failed_total` growing; `anchor_start_failed` > 1 % of `anchor_starts_update` over 10
   updates (B); with double, `t_overlap_wait_s` > 25 % of `t_rollout_s` for 10 updates (A; the mode may not change
   within the line, so stop and report); an isolation error; an eval-at row with `error`. After a fix, resume from the
   last checkpoint with unchanged flags (`config_diff` empty apart from `max_updates`).
2. **Budget stop**: cap **115 units** for the round (both GPUs together). At the cap, stop both lines and report at the
   highest comparison point both reached. Nothing extends a line automatically.
3. **Harm stop (B only)**: if at two consecutive comparison points from u1764 on the dev-128 greedy-off paired 95 % t
   CI of B − A is entirely below 0, stop B and report "harvest hurts (interim)"; A continues.
4. **No other early stop.** A plateau does not stop A: the deliverable is the fixed u3064 endpoint, not a best point.
5. **Follow-up gate**: a positive harvest result (§4.3) is replicated with independent training seeds (`--init-seed 2
   --sample-seed 2 --env-seed 2 --seed-stream-prefix SP2`, forked from the SP2 replication line's u764 if it exists)
   before harvest becomes the main line. That replication needs a new user approval.

## 8. How owner D's macro env joins

Owner D (`train/w3-macro`, WIP) adds opt-in room macros (`--macros rest,shop`): at a rest site SMITH becomes one
candidate per upgradable deck card, in a shop the card removal one candidate per removable card, each a full pick +
confirm in one step, so the SMITH → select → cancel loop cannot happen. Facts that decide how it joins:

- It changes C# (`RoomMacros.cs` in `Sts2Sim.Vec`), so it needs a new NativeAOT build, a **new AOT key** and a new
  bundle; a running line cannot pick it up without a restart on the new bundle.
- **Spec-compatible**: no buffer, enum or vocab change; `encoder_version` is the same with macros on or off, and
  `check_spec_compat` reports identical model inputs (no widening). Any checkpoint (this u764 source, any W3 pinned
  point) resumes with `--macros rest,shop`.
- Behaviour shifts on resume: the learned SMITH row meant "open the prompt"; with macros the rows mean "upgrade this
  card". Expect a transient after the switch.
- Eval: `sts2train eval` plays a checkpoint with its own `config.macros`, and a macro line's `--eval-at` rows are played
  with macros. Progress on the same dev / ab seeds stays comparable across lines (same game, seeds and limits); the
  action sequences do not (a replay needs the same macros). The real-game twin and the combat lookahead have no macro
  mapping.

Joining options (pre-registered):

1. **Third line (preferred; needs a third GPU, ≈55 units)**: line M = line A's recipe + `--macros rest,shop`, forked
   from the same u764 checkpoint, compared M − A at the same matched endpoints with the rules of §4.
2. **Swap-in at a fixed point (two GPUs only)**: when GPU B frees up (B finished, or stopped by §5.3), fork M from
   **A's** latest comparison-point checkpoint (`pinned-0001764.pt` … `pinned-0003064.pt`) with `--macros rest,shop`
   and compare M against A at matched update numbers after the fork (M continues A's stream counter, so common random
   numbers hold). Never switch a running line's env.
3. Before either: D's C# default-path identity tests, the Python macro tests and a CPU smoke on raven, the new bundle's
   `sts2vec check`, and a 3-update CUDA resume of the u764 checkpoint with `--macros rest,shop` (spec-compat line in
   `train.log`, no widening).
