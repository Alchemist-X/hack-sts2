## 2. 架构（一页）

```
反编译的游戏（git-ignored） ──源码移植──▶ sim/  C# 规则内核（Route C，可克隆、无头）
                                              │  Sts2Sim.Vec：批量 VecEnv + 观测编码器 + C ABI（NativeAOT .so）
                                              ▼
                                   sim/tools/vec  sts2vec（Python 绑定，eval / bench）
                                              ▼
                                   sim/tools/train  sts2train（PPO、评测入口、compare、report-card）
                                              ▼
                    Colab A100 ×2（训练包 sts2train-<sha>.tar.gz） ──gcs_sync──▶ 私有 GCS 桶（checkpoint / 评测）
```

- **模拟器（Route C）**：`sim/` 是从反编译游戏源码 1:1 移植的规则内核（游戏作者已书面许可，学术研究项目；反编译树不入库，
  移植后的源码入库）。真游戏只做 oracle 与"考场"（`scripts/live/`：训练好的 checkpoint 通过孪生模拟器在真游戏上逐决策对拍）。
  计划与门：`docs/p0-sim-port-plan-2026-10-28.md`、`docs/p1-sim-full-port-plan-2026-11-01.md`；理由：`docs/a10-first-principles-review-2026-10-27.md`。
- **Vec ABI + sts2vec**：`sim/VEC.md`（实现）与 `sim/ENV_SPEC.md`（给策略作者的一页）。`VecEnv` 批量 step / reset / snapshot / restore，
  ABI 2 加了搜索用的 branch / restore（`sts2vec_branch*`）。动作是"候选表"里的一行；宏动作（`--macros rest,shop` / `all`）把多步
  UI 选择折成一步（`docs/prompt-macros-v2-2026-11-04.md`、`docs/notes-macro-env-for-gpt-2026-11-04.md`）。
- **sts2train PPO**：`sim/tools/train/README.md`。mid 预设：d_model 192、state 384、depth 3、6 heads，**2,904,208 参数**，
  aux heads（胜率 + 战斗结束 HP）、deck counts、获取塑形（卡 0.003 / 遗物 0.01 / 升级 0.012）、目标 = 协议进度 + 胜利奖励 1.0、
  γ 1.0、λ 0.99、lr 3e-4、clip 0.2、1 epoch、minibatch 4096、bf16 + `torch.compile`。
  **2048 局 × 64 步 = 131,072 环境步 / update**。Colab A100（12 vCPU）上约 12.4–12.9 s / update；`w3m-a` train.log 最后 2000 个
  update 的中位数：env 5.4 s、infer 2.5 s、update 3.2 s（其余为日志 / 同步开销）。GPU 不是瓶颈，CPU 侧的模拟器是。
- **训练开局**：种子流（`--start-mode stream`，`SP1-SILENT-<n>`，永不重复，与所有评测集隔离）；不用人类存档、不用旧权重。

## 6. 主要发现

1. **行为审计**（`diag-2026-11-05/behaviour-audit-a-u5064.md`，线 A u5064 的 dev-128 回放）：火堆 453/453 全部休息、**0 次锻造**；商店
   **0 次删牌**（203 次有删牌行）；锻造 / 删牌行的概率 0.000，训练采样也碰不到；能避开精英时 **0/257 选精英**；跳卡只 6.3%，牌组 ~30 张；
   Act 2 boss 2/21。**塌缩早于宏动作**（`rest-collapse-history.md`：C1 u764 已经 325/325 休息）。这是第三、四轮的依据。
2. **奇巧（Sly）**：有得弃时 92% 弃奇巧牌，机制被利用了（`sly-check-a-u5064.md`）。
3. **决策时搜索为负**（`lookahead-on-m3064.md`、`lookahead-hp-boss.md`）：M u3064 上 turn / value+hp / K=8 为 −0.079 [−0.108, −0.050]；
   只在 boss 战搜、按 HP 打分、K16 / R4 全部低于贪心。原因是价值头：它估的是"剩余进度 − 塑形势能"，29% 的战斗状态 V<0，
   同一决策内 Q 差中位数 0.0039（`value-head-discrimination.md`）。瓶颈是叶子打分，不是搜索量。ExIt 因此搁置。
4. **HP 势能塑形**已实现（wave 8）但还没训练：行为审计显示运营层塌缩是更先决的问题，所以顺延。
5. **人类数据**：SILENT A10 只有 1 局人类对局（~911 个决策），行为克隆不可行（`human-data-inventory.md`）。
6. **harvest**（难局起点课程）对进度的效应在 ±0.01 内（B 对 A）；**循环成本**稳定地消灭 UI 循环，进度增益小且不确定（种子 2 未复现 +0.023）。

## 8. 怎么跑测试

**不要在本机（Mac）跑 dotnet / pytest / 模型构建**——一律走 raven 上的测试箱：

```bash
scripts/test_remote.sh                                                     # build + train / vec / eval 三套
scripts/test_remote.sh --suites train                                      # 只跑一套
scripts/test_remote.sh --suites none -- uv run --project sim/tools/train pytest -q <test files>   # 指定测试
```

它把 HEAD 的已提交树 `git archive` 到 raven 的 Docker 测试箱（`sim/Dockerfile.testbox`），不带任何密钥；未提交的改动不会被测。
需要 raven 的 SSH 访问（向 owner 申请）。最近一次全套门禁：train 237 / vec 132 / eval 84（wave 8 合入，研究日志 15:40）。

## 9. 数据在哪里

- **GCS 桶**（私有，`runs/<run>/`：checkpoint、pinned、metrics / evals / status / config / train.log、评测目录；`bundles/`）：
  访问需要 owner 授权；服务账号 key 只在 owner 本机与 VM 上，**不进仓库、不打印、不转发**。桶没有对象版本，覆盖即丢。
- **录制器会话与人类轨迹**（`~/Library/Application Support/Sts2Recorder/sessions/`）：永远不入库；游戏存档只拷贝不修改。
- **监控页**是 owner 的私有 claude.ai artifact，不对外；数据源就是桶里的 evals / metrics。
- **raven** 上的搜索 / 审计实验目录：`/data/raven/hack-sts2/`（lookahead、audit、testbox）。
