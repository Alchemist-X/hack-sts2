# 五角色 A10 >50%：第一性原理评估与路线规划

日期：2026-10-27。性质：独立评审与规划，只读完成；未启动游戏、训练、GPU 或付费调用。证据来源：主检出脏工作树的训练实现、本机 `output/` 实验产出、反编译规则树耦合审计、人类录像语料盘点、全部规划文档、外部公开基准。

---

## 0. 结论

1. **目标是 SOTA 级研究目标，不是工程执行目标。** "五角色 A10 各自 >50%"介于"强人类"与"顶尖人类"之间，超过所有公开 AI 系统在 STS1/STS2 上的已知成绩。它没有已验证配方，必须按"假设→最小实验→证伪"组织，不能按里程碑排期承诺。
2. **当前方向半对。** 真实引擎 headless 化、动作协议、回放一致性、审计纪律——这套"考场与真值 oracle"是对的且保值。但学习管线（哈希 MLP + 塑形奖励 + γ=0.99 PPO + 15 决策/秒采样）没有任何通向 50% 的机制；过去数周的主要投入在降低工程风险，没有降低科学风险。暂停是正确的。
3. **单点最大决策：规则级、可克隆、快三个数量级的模拟器。** 这不是三条路线里的偏好，是目标反推出的必要条件（§2b 的教师天花板论证）。耦合审计显示它可行，且比"月份级悲观估计"更可控。
4. **算法主线：搜索教师 + 蒸馏（Expert Iteration）**；人类语料做冷启动与价值预训练；PPO 降级为对照和后期微调工具；奖励改为 γ=1 纯胜负。
5. **下一步唯一最有信息量的事：2–3 周的战斗核心差分原型（P0）**，其余一切决策等它的结果。费用近乎 $0。

STS2 的 A10 被社区对标 STS1 的 A20（第三幕双 Boss，当前进阶上限）；反编译确认 A1–A10 全部修正项（精英 5→8、金币 ×0.75、药水栏 −1、诅咒、商店涨价、稀有度削减、约 100 个怪物类内联的 HP/伤害提升、终幕双 Boss）。

**统计验收账**：要在 95% 单侧置信（含五角色多重校正）下证明每角色真实 >50%：观察胜率 ~60% 需每角色 ~250–400 局；~55% 需 ~600–1,000 局。真实引擎全流水线吞吐 ≈1.7 决策/秒/进程、一局 ~900 决策 → 一局 ≈9 分钟/进程；最终验收 5×500 局 ≈ 10–16 进程·天。可行，但说明**真实引擎只能当考场，不能当学习环境**。

**决策量账**：通关局 ~900–1,100 决策（语料胜局动作记录中位数 1,085，配对记录约虚高 15–20%）。胜负信号要跨约 10³ 步传播——这是信用分配问题，不是算力问题。

## 2. 第一性原理拆解

胜率 = f(环境吞吐与可克隆性 × 学习信号来源 × 表示容量 × 搜索)。

### (a) 技能分解：宏观才是难点

- **战斗微观**（给定卡组出牌/目标/药水）：5–15 回合短程、公开信息充分，搜索可逼近最优——STS1 先例已证明。
- **整局宏观**（走图/选卡/商店/休息/事件，50+ 层）：sts-rl-agent 的教训——战斗 MCTS 开到 50k 模拟而宏观网弱，A0 也只有 14%。宏观决定你带什么卡组进战斗；高手优势主要在 HP 经济、卡组成长曲线与风险定价。
- 因此项目的本体学习对象是：**V(公开 run 状态) = 通关概率**。战斗搜索的叶评估、宏观决策、风险定价全都挂在这个价值函数上。

### (b) 学习信号三来源 → 教师天花板论证

1. **人类轨迹**：126 局 / 84,849 条动作记录 / 34 胜；A10 水平 ≈11%，92% 在 v0.107.1。→ 量级和质量都够不着目标，但做 BC 冷启动、价值预训练、差分测试向量和深局面开局库正合适。
2. **LLM**：A10 约 1/4 胜率、单局亿级 token → 批量产教学数据不经济。LLM 的真实杠杆在**写代码、写测试、移植规则**，不在打游戏。
3. **搜索自举**：唯一能制造"超越一切现有教师"信号的来源。前提：快（≥10³ 决策/秒/核）、可克隆（ms 级）、规则精确的模拟器 + 确定化/信念采样（未知牌序按公开分布重采样，绝不读真实隐藏 RNG）。

**硬结论：当前不存在任何达到"A10>50%"水平的教师（人类 11%、LLM ~25%、规则 bot 0%）。纯模仿类方法的上限是教师水平；不做搜索自举，目标在逻辑上不可达。**

### (c) 环境物理账

- 真实引擎服务时间 ≈190 ms/决策（仅主线程快照 41 ms），全流水线 ≈1.7 决策/秒/进程；协程态不可 fork，存档仅房间级（秒级）。
- 规划中的 100–500 决策/秒是未实测目标；即便达成，与搜索需要的"每决策数百–上千次模拟"仍差 2–3 个数量级，且永远缺克隆。
- → 继续优化引擎吞吐是在优化非瓶颈。它的正确角色：**真值 oracle + 正式考场 + 部署目标**。

## 3. 现状评估

### 保值资产（无论选哪条路线）

| 资产 | 为什么保值 |
|---|---|
| 隔离 headless 真实引擎 + 完整候选/决策回执/过期拒绝/自然终局协议 | 即是 oracle 与考场，也是 P0 差分对照物 |
| 普通/加速回放一致性方法论（38/39 一致） | 直接升级为模拟器差分验证法 |
| 人类语料 126 局（含 native `replay.mcr` 与特权 events 通道） | 测试向量 + 预训练 + 课程开局库 |
| 反编译树 + 本次耦合审计 | 规则真值来源；90% 内容纯 C#；游戏自带 ChecksumTracker / CombatReplay |
| 评审纪律（资格门、不删分母、审计文件、预算口径） | 最终验收的可信度基础 |

### 不通向目标的部分

1. **学习管线三重先天不足**：哈希 MLP（无实体结构、无记忆、有损压缩）+ 塑形奖励为主目标（楼层/HP 会诱导"苟楼层"而非赢）+ γ=0.99（~10³ 步的局，有效视野 ~100 步，终局 ±5 对早期决策不可见）。观测证据完全一致：所有评测 0 胜、最高 17 层。且这与项目自己的设计文档（`training-and-evaluation.md`：γ=1、以终局胜利为目标、GRU、先人类 BC）相反。
2. **吞吐口径误导决策**：14.8–16.6/秒是"战斗窗口内检查点回放"（共享 4C8T 主机、每进程 16 决策）；含启动的完整流水线只有 ~1/秒/进程。10⁸ 决策 ≈170 进程·天——无模型 RL 的样本需求在此环境不可达。
3. **云 GPU 管线是过早优化**：CPU 更新 0.23 s vs 采样 96 s，瓶颈从不在 learner。
4. **版本分裂**：A10 全部实战证据在 v0.107.1，训练环境 v0.111.0，语料 92% 在 v0.107.1。
5. **目标维度缺基建**：`evaluate_training_runs.py` 写死 IRONCLAD/A0；五角色与进阶参数未实现。

（口径修正：交接声明中 BC 贪心 14.43 层、v14c 53 局等原始文件只在服务器，本机核对不了；H100 实机 62 步的原始停止原因是 FastEnvError 连接故障，"用户停机"只出现在 pause-audit。本机能核对的数字全部吻合。）

### "方向正确吗"的直接回答

基建方向正确且已到"能当考场"的水平；学习方法还没踏上有任何先例支撑的路径。最大的问题不是"PPO 对不对"，而是**资源投在了"让训练跑起来"上，而不是投在"降低决定成败的三个未知"上**：模拟器可行性、教师信号来源、表示容量。暂停并转向是对的。

## 4. 决策一：环境路线 —— 双轨

| 路线 | 审计证据 | 判定 |
|---|---|---|
| A. 继续优化真实引擎 | 上限 100–500/s（未实测）；协程态不可 fork；单例全局态 | 退役为**考场**，不再加码 |
| B. 托管原 DLL 无头运行（TestMode=on + `CardSelectCmd.UseSelector` 注入 + MockRng） | 官方测试缝存在（277 文件引用 TestMode；VFX 返 null、等待短路、ActionExecutor 直 await）；但 Logger 静态构造调 Godot OS，仍需 Godot runtime/垫片；单例 → 一进程一局 | **oracle 自动化**：正确性最高、数天–数周可立，用来批量生成差分测试向量，不是训练环境 |
| C. 源码移植规则内核（以反编译为规则真值） | 数值内核（`Hook.cs` 11.8k 行、伤害/格挡/HP、能量）纯 C#；RNG 为 xoshiro256** 按用途 12+3 条命名流、确定性播种、自带 MockRng 注入缝；~90% 卡牌/遗物/能力类不碰 Godot；规则通知走 C# event 非 Godot 信号；游戏为联机锁步设计（ChecksumTracker、CombatReplay 可直接当验证基准） | **训练主环境**：重写 ~20 个 `*Cmd` 门面 + CombatManager/RunManager/ActionExecutor + 剥 VFX 块；状态设计为可序列化/可克隆 |

**推荐：C 为主线，B 为 oracle，A 为考场。**

工作量再估（基于审计）：内容 1,418 个文件（卡 596 / 遗物 300 / 能力 268 / 怪 121 / 事件 68 / 药水 65），每张卡 100–200 行中真实逻辑 20–50 行（其余是 async 状态机样板）；怪物/事件/药水约半数要剥 UI 块（多数已被 `TestMode.IsOff` 或 `?.` 包住，可机械删除）。配合 agent 流水线"逐卡移植 + 差分测试"（oracle 可自动生成无限测试向量：托管引擎脚本自玩，逐决策比公开状态与校验和），战斗核心 2–3 周、单角色全内容 1–2 个月、五角色再 1.5–2.5 个月（高度可并行）。旧的"月份级"量级判断正确，但不可压缩的部分是**差分验证的严谨度**，不是打字量。

**已知陷阱**（移植时必查）：`CardRarityOdds` 的静态字段按进阶只初始化一次（同进程多局会错）；`TheArchitect` 事件的 VFX 列表长度参与规则 RNG 消耗，删 VFX 必须保留随机调用次数；A8/A9 数值散在 ~100 个怪物类里没有中心表；遗物选择没有测试注入缝（只有 UI/回放通道）；反编译有 26 处 OpCode not supported 与 9.1 万行缺引用注释——**先带引用程序集重新反编译**。

**补丁漂移**（EA 游戏会更新）：版本钉死（建议钉 v0.111.0 或重启时的最新稳定版，把证据链全部迁到同一版本）；每补丁跑差分回归套件（语料 replay + 随机自玩向量）定位规则改动，录像器照常收新版本人类局。

**克隆语义**：决策点都是协程静止点，在静止点序列化快照（游戏本有存档与锁步校验，状态核是 KB 级）；搜索内未知信息一律 MockRng 重采样，本来就不该复制真实隐藏流——所以"协程中态不可 fork"不构成障碍。

## 5. 决策二：算法主线

**Expert Iteration（搜索教师 + 蒸馏）**，单人随机不完全信息版：

- **搜索教师**：决策点确定化 IS-MCTS/随机化搜索；战斗叶评估接整局价值网；宏观节点（选卡/走图/商店/休息/事件）同框架——分支小、深度浅、价值网主导。确定化样本来自公开信念分布（牌堆组成计数、已知牌序前缀），绝不读真实隐藏 RNG。
- **学生网络**：1–10M 参数实体编码（卡/遗物/能力/敌人嵌入 + set attention + 候选 pointer 打分），双头（policy + 胜率 V）；γ=1，win∈{0,1} 是唯一奖励；HP/楼层只进辅助预测头，不进奖励标量。
- **自举循环**：搜索标签 → 蒸馏 → 新网指导搜索，2–4 代。外部佐证：ChessBench（1,000 万局搜索标签蒸馏出 2895 Elo 无搜索棋力）、VPT/AlphaZero 家族（先模仿后放大）。
- **冷启动**：人类语料 BC + 价值预训练（126 局的正确用途：把搜索从随机先验里救出来）；课程 = 从人类/自玩中局状态开局（语料提供真实深层局面分布，避免"必须先会前期才能练后期"）。
- **PPO/V-trace**：保留为蒸馏后的在线微调与最小对照（此时策略已不差，on-policy 样本才有效率）。
- **部署双形态**：a) 纯蒸馏网（已验证 CPU P99 7.6 ms 路径，保底）；b) 网 + 本地限时搜索（Mac 上 sim 10–100 ms/决策、异步执行不卡帧，冲 50% 的形态）。两者都满足"本地 CPU、不逐动作上云"。

## 6. 阶段计划（每阶段带证伪门）

| 阶段 | 内容 | 晋级门 | 失败分支 | 时间 |
|---|---|---|---|---|
| **P0 战斗核心差分原型** | Ironclad 子集（起始卡组+~30 卡/10 敌/15 能力）源码移植；B 路线 oracle 服务化；差分=同种子同动作逐决策比公开状态+校验和 | 支持子集回放一致率 ≥99.9%；≥10³ 决策/秒/核；静止点快照/恢复 ≤1 ms | 移植不可行 → 转 §9 降级阶梯 | 2–3 周 |
| **P0.5（并行）** | 带引用重新反编译；`evaluate_training_runs.py` 角色/进阶参数化；版本钉死决定 | — | — | 同期 |
| **P1 搜索价值验证** | 固定战斗套件（从语料深局面抽样）；比 HP 损失分布：搜索 vs 用户本人 vs BC vs 随机 | 搜索中位损血 ≤ 人类 | 搜索不如人 → 查 sim 正确性/价值函数，再不行转降级 | 2–3 周 |
| **P2 整局 sim + ExIt（1 角色）** | 地图/商店/事件/奖励/A10 修正全量；ExIt 2–4 代；**最大科学风险位** | sim 内 A10 ≥55%；随后真实引擎 200 局 ≥45–50%（含差分漂移核查） | 停滞 30–40% → 按序补救：宏观搜索预算↑、价值集成、人类宏观先验、换角色；仍停滞 → §9 | 4–8 周 |
| **P3 五角色横扩** | 内容移植流水线 + 每角色覆盖清单 + 回归；统一网条件化，负迁移则分头蒸馏 | 每角色 sim 开发集 ≥55% | 个别角色拖后腿 → 专用模型 | 6–10 周（可并行） |
| **P4 冻结验收** | 每角色 500–1,000 局真实引擎新对局；Wilson 下界 >50%，五角色校正；帧时三条件对照（无模型/空闲/执行） | 全部达标 | 未达标 → 报告真实数字，不粉饰 | 1–2 周 |

**时间合计：乐观 4–6 个月，现实 6–12 个月**（单人 + agent 协作）。

**钱**（假设显式）：移植与差分几乎全是 agent/工程时间，云计算 ≈$0；训练为 CPU 搜索主导——假设移植版 sim 300–900 完整决策/秒/核，教师一局 5–30 CPU·min（400–1,600 模拟/决策），64 核 ≈ 每天 3,000–18,000 标签局，每代 1–5 万局 → 1–5 天/代；Huginn 可覆盖则近 $0，云替代 $500–3,000；蒸馏 GPU <$200；真实引擎验收在 Huginn 免费。**主要成本是时间和 agent token，不是 GPU。**不给任何"到期达标"保证：P2 的 sim 内胜率是第一个真实的可达性检查点。

## 7. 三大风险与最有信息量的实验

1. **模拟器正确性与补丁漂移（系统性）**——模型必然利用 sim 的 bug。缓解：差分 oracle 常态化、版本钉死、每补丁回归、真实引擎终审。
2. **宏观信用分配不足（科学）**——sim 内胜率可能停在 30–40%，这是最可能卡住 50% 的地方，也是没有先例兜底的部分。缓解顺序见 P2 失败分支；它失败的信息本身就值回成本。
3. **内容覆盖 × 单人带宽（执行）**——1,418 个内容文件的移植与验证。缓解：agent 流水线、覆盖清单、先一个角色打穿再横扩。

**下一步最有信息量的实验 = P0**：一个实验同时证伪"移植可行性、吞吐量级、差分 oracle 方法、agent 生产率"四个最大未知，费用近 $0，且不论结果如何都直接决定路线。

## 9. 降级阶梯（证据推翻主线时）

- **P0 失败**（移植不可行/吞吐不达）→ B 托管 oracle 当慢速教师（房间级课程 + BC + 小预算搜索），目标降为"单角色 A10 >50%"或"五角色 A5"；"五角色 A10>50%"不再承诺。
- **P2 失败**（sim 内到不了 ~50%）→ 三选一：①人机协作造高质量教师数据（用 sim 的分析工具辅助用户本人打出高水平 A10 局，再模仿+搜索放大）；②缩目标；③停，并把"当前配方不足"作为结论成果。
- 任何时刻：考场基建、语料、反编译审计结论照常保值；该项目同时是 benchmark 工程，中间产物（每角色基线、搜索教师强度曲线）本身有发表/对照价值。
